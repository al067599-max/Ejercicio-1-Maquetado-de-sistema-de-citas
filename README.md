Instrucciones: Lee atentamente la siguiente descripción de un sistema de software.
Una empresa tiene interés en ofrecer un servicio de citas para que las personas con intereses afines
puedan entrar en contacto y conocerse, además de recabar datos que puedan ser de utilidad para
empresas publicitarias. El comité ejecutivo de la empresa tiene las siguientes ideas en mente:
1. La aplicación debe ser simple de utilizar, con un registro inicial mínimo. Cuando una persona
acceda por primera vez, debe solicitarse una cantidad reducida, pero suficiente, de datos
para identificarlo (por ejemplo, el código postal para saber en dónde se encuentra, y una foto
para identificarlo.
2. Una vez proporcionados estos datos, se debe mostrar al usuario personas cercanas a la
ubicación dada. La aplicación debería poder realizar búsquedas o filtros (por ejemplo, por
sexo, género, edad, intereses, etc.).
3. Si el usuario escoge una persona, se debe mostrar un formulario de contacto, en dónde la
persona puede elegir por qué medio quiere ser contactado (en persona, por teléfono, por
correo, por redes sociales, etc.) y enviar un mensaje a la persona seleccionada para saber si
acepta o no.
4. El usuario también debe tener acceso a los mensajes que le han llegado, y al abrir uno, debe
decidir si acepta la solicitud o no. En caso afirmativo, se muestran los datos de contacto de
la otra persona.
5. El usuario también debe tener un perfil en el cual pueda poner más detalles opcionales sobre
él mismo, como sus gustos, hobbies, intereses, etc.
6. Como la aplicación hace uso de datos personales, debe tener un aviso de privacidad en
dónde se indique de manera explícita el uso que se hará de ellos, para que el usuario confirme
que está de acuerdo.
Utilizando la descripción anterior, elabora una maqueta de la aplicación solicitada por la empresa.
Diseña tu aplicación con base en un mecanismo de navegación que divida el proceso en etapas. No
muestres el formulario completo en una sola pantalla, divide el funcionamiento en varias vistas
manejables que vayan guiando al usuario.
Debes implementar la parte visual de la aplicación, es decir, el diseño de la interfaz gráfica de usuario,
y en cuanto a la programación debes implementar la navegación, es decir, permitir al usuario el pasar
de una pantalla a otra (o regresar a la anterior). Todo lo demás, de momento, no importa si no tiene
funcionalidad (por ejemplo, no importa si tu aplicación no guarda los datos). Si lo requieres, puedes
usar mockups o dummies de los datos para visualizar su aspecto dentro de la aplicación.
Para obtener calificación completa, la aplicación deberá hacerse en JavaFX. Las aplicaciones en
Swing tendrán una calificación menor.
Para la evaluación se tendrán en cuenta los siguientes aspectos:
1. La aplicación permite capturar toda la información requerida (10%)
2. La aplicación se encuentra compuesta de varias pantallas (10%)
3. Cada pantalla utiliza los componentes adecuados para capturar la información requerida
(15%)
4. La aplicación tiene un estilo único, original y distinto que permita reflejar la autoría del trabajo
(20%)
5. La aplicación implementa el proceso de captura de forma intuitiva (10%)
6. La aplicación es estéticamente agradable y con una apariencia profesional (10%)
7. La aplicación fue creada haciendo un uso responsable de IA (15%)
8. La aplicación fue entregada en tiempo y forma (10%).
Como entregable, deberás crear un proyecto de Maven con todos los recursos (archivos FXML,
imágenes y código fuente) que también incluya una carpeta llamada screenshots en dónde coloques
capturas de pantalla de cada una de las vistas de la aplicación. Si el proyecto no contiene las
capturas de pantalla, no tendrá calificación. Este proyecto deberá subirse a un repositorio público
de GitHub.
